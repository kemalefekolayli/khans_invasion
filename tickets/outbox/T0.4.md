DONE

## Summary
`FogOfWarManager` now tracks only provinces that are actively lerping in a new `activeLerpProvinces` (`HashSet<ProvinceModel>`) field. `Update()` early-returns when the set is empty and otherwise iterates only the active set, removing a province once its color reaches its target (epsilon compare). Provinces enter the set at every reveal/peek entry point: `DiscoverProvince` (isRevealing starts), `UpdateAdjacentProvinces` (isBorderPeek starts, covers both initial fog init and neighbor peeks), and `OnProvinceOwnerChanged` (target color changes, so border-peek provinces must re-lerp). Lerp formula, speeds, thresholds, and targets are unchanged; only the per-frame iteration cost is reduced.

## Notes / Issues
- I could NOT run Unity or the simulation harness from the CLI, so "compiles cleanly" is verified by careful code review only (types, signatures, namespaces, brace balance). A compile pass in Unity Editor is the remaining confirmation.
- Design decision: removal is deferred into a reused `settledProvinces` list because C# throws `InvalidOperationException` if a `HashSet` is mutated during `foreach`. This avoids per-frame allocations (no copy/snapshot each frame). In steady state `Update()` allocates nothing and does ~zero work.
- The original exact-`Color !=` check meant asymptotically-lerping provinces never settled; the new epsilon stop is intentional per the ticket and visually indistinguishable.
