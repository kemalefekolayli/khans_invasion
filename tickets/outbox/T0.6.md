DONE

## Summary
Replaced all three `Physics2D.OverlapPointAll` calls in `SelectableGeneral.cs` (`CheckCurrentProvince`, `CheckCityCenter`, `IsPositionBlocked`) with the non-alloc `Physics2D.OverlapPoint(position, filter, buffer)` overload returning an `int count`, processed via `for` over the first `count` entries of a single reusable `Collider2D[64]` buffer field. The `ContactFilter2D` is built once in `Awake` (`useTriggers = true`, `useLayerMask = true`, `layerMask = Default`) and cached. `Update()` now only re-scans provinces/city centers when the general's position moved > 0.05 units since the last scan (idle generals skip the sweep entirely); `TeleportTo` still forces a scan. `IsPositionBlocked` runs per `FixedUpdate` only while moving (unchanged) and now shares the same buffer/filter.

## Notes / Issues
- Buffer size 64: `OverlapPoint` truncates at the buffer length. A single point overlaps at most a few province polygons + 1 city-center circle + a small number of unit colliders; even under pathological truncation, large province/city-center colliders are retained before small unit colliders (which are tag-filtered out anyway). No practical regression risk.
- Idle-skip threshold 0.05: the last scanned position lags the actual position by at most 0.05 units (≈ one frame at moveSpeed 5). Province/city-center events can fire up to ~1 frame later than before, never missed (crossing a province twice within 0.05 units is geometrically impossible for real map polygons).
