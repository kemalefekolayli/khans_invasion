2. **Panel slot limitation (needs planner/human decision):** `QuestPanelCanvas.prefab` `QuestPanelController.questItems` has only 5 slots, so the panel only renders quests id 0..4. This predates T1.4 (Quest_6 "Destroy a nation" was already invisible). The prefab is NOT in this ticket's Files Touched, and hand-editing a prefab YAML (cloning QuestItemUI nodes with new fileIDs) is risky with the editor open. Recommend a small follow-up ticket to expand the panel (e.g. scrollable quest list or more QuestItemUI slots) so "all new quests appear in the panel" (Done When #1) is fully satisfiable.
3. **Design decisions:**
   - Value quests display live value as progress (e.g. `250/300`) because `CheckValueQuests` writes the current value into `questProgress`.
   - Income and population are computed LIVE from provinces (not the cached `PlayerNation.TotalIncome`/`PopulationSize`) because `Builder` and `PopulationProcessor` do not trigger `RecalculateStats` — the cache can be stale by a turn, which would delay completion.
   - `RecruitTroops` is counted on `OnArmySpawned` by army size for player-owned armies. Limitation: recruiting into an EXISTING army (`AddSoldiers`) does not fire `ArmySpawned`, so that case is not counted; the typical flow (create a new army via Get Army) IS counted. Fully tracking per-recruit amounts would require an event from `GetArmyButton`/`Army` (out of scope of Files Touched). Also, quest-reward general armies (NewGeneral rewards) increment RecruitTroops progress since they are player armies — acceptable, documented.
   - `CheckValueQuests` only fires `OnQuestProgressUpdated` when the value actually changes, avoiding UI refresh spam.
4. **SimulationController** does not reference quests; no harness impact. Unity batchmode compile was intentionally skipped (editor open) — the Tester agent should run it after merge.
