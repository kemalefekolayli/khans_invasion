## Notes / Issues
- Chose the **registration** approach (option b) over a one-time `FindObjectsByType<ProvinceNameDisplay>` collection because it matches the codebase style (`ProvinceNameDisplay` already calls the static `GameFontManager.ApplyCityNameFont`), stays correct if a display/text is created at runtime, and avoids even a one-time full scan/allocation.
- Registered in `OnEnable`/`OnDisable` rather than `OnDestroy`: `Awake` resolves `provinceNameText` (inspector or `GetComponentInChildren`) before `OnEnable`, and `OnDisable` fires on scene unload while object references are still valid, so the `HashSet` never retains stale references to destroyed texts.
- `HandleSceneLoaded` does not clear `cityNameTexts`; the registry is kept accurate by the enable/disable lifecycle (GameFontManager is `DontDestroyOnLoad`). The previously-existing `"ProvinceNameText"` name check and `GetComponentInParent<ProvinceNameDisplay>` walk were removed as redundant now that the display registers its resolved text.
