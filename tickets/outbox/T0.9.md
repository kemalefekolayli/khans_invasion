# RESULT: T0.9 — Pool floating-text popups (reduce GC churn from raid/siege/pop events)

## Status
DONE

## Summary
Replaced `Instantiate` + `Destroy` popup lifetime in the three popup spawners with a shared, small generic `ComponentPool<T>` helper (preallocates `poolSize` items under a pooled parent, hands out inactive items, expands up to 2x base, returns items by deactivating). Each spawner now owns a per-type pool (`LootPopupSpawner` → `FloatingLootText`, `SiegePopupSpawner` → `FloatingSiegeText`, `PopulationPopupSpawner` → `FloatingPopupText`). The animation components call back into their pool (`pool.Return(this)`) when their animation finishes instead of `Destroy(gameObject)`, falling back to `Destroy` only when no pool is bound (needed because `GetArmyButton.cs` also creates `FloatingPopupText` popups and is out of scope). Text, colors, font sizes, rise speed, lifetime, and spawn positions are unchanged; per-message text/color/font-size are still applied at spawn time, static appearance is configured once per pooled object.

## Notes / Issues
- **Design decision**: extracted a shared `ComponentPool<T>` helper (the ticket's Nice-to-have) because it strictly reduces the diff vs. 3 inline copies of the smoke controllers' pool logic (which were left untouched — they are not in the ticket's Files Touched). `Get()` returns an inactive item and expands up to 2x base size; returns `null` (popup skipped) only if every item is in use at max size — same limitation the reference smoke controllers accept.
- **Pool sizes**: loot 20, siege 20, pop 40 (max 40/40/80 concurrent). Population growth fires for all player provinces in one turn (`PopulationProcessor`), so the pop pool is the largest. If a player ever owns more provinces than 2x base and all grow in one frame, the overflow popup would be skipped — bump `PopulationPopupSpawner.poolSize` in the inspector if the map has very many provinces.
- **Behavior nuance**: pooled objects now cache `Camera.main` in the billboard components' `Start()` once instead of re-caching per popup — no visible change (single main camera).
- **Removed dead code while touching files** (anti-slop): the unused 1-arg `FloatingLootText.Initialize` overload, the empty `PopulationPopupSpawner.Start()`, and a duplicated `<summary>` doc block.
- **Prefab path** (`LootPopupSpawner.lootTextPrefab`): factory now `Instantiate`s the prefab once into the pool; if the prefab lacks `FloatingLootText` it is added (previously such a prefab spawned a static, never-destroyed text — a latent bug now fixed so pooling works). `BillboardText` is still only added in the dynamic path, preserving prior prefab behavior.
- **Out of scope**: `GetArmyButton.cs` also spawns `FloatingPopupText`/`PopupBillboard` popups; it keeps its existing Instantiate+Destroy behavior (pool is null → Destroy fallback). Was not modified to avoid scope creep.
