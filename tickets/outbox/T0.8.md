## Notes / Issues
- **Hex cache decision:** `NationLoader.HexToColor` does **NOT** have an existing cache (verified by reading the full file — it parses the hex string every call). No second cache was built. Per the ticket's preferred "simplest correct approach," the flag visual itself caches the last owner and recomputes the color only when the owner reference changes. A per-`NationModel` dictionary cache was deliberately not added: `nationColor` is immutable at runtime (grep shows the only write is `NationLoader.LoadNations` line 44), so the color can only change together with an owner-reference change, making the pointer compare equivalent to the "owner changed OR color changed" requirement. Event-driven refreshes (`OnProvinceOwnerChanged`, `OnPlayerNationChanged`) still call `RefreshFlag` directly, so conquest/nation-change recolor is preserved.
- **B-NTH (left):** `PlayerNationGUI.GetKhanGeneral`, `RaidButton.GetCurrentRaider`, `EnemyProvinceButtons.GetCurrentRaider` still use `FindObjectsByType<SelectableGeneral>` fallbacks. `GeneralSelectionManager.RegisteredGenerals` does exist, but swapping changes behavior: `FindObjectsByType` finds any active scene `SelectableGeneral`, while `RegisteredGenerals` only contains generals that completed `RegisterGeneral` (OnEnable/Start ordering vs. the manager singleton). These call sites are event-driven (button clicks / loot updates), not per-frame, so there is no perf cost. Per the ticket's "if it risks a behavior change, leave it," they were left unchanged.
