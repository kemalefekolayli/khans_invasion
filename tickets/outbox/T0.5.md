# RESULT: T0.5 — ArmyBattleManager: stop O(n²) scan + per-frame list allocations

## Status
DONE

## Summary
Throttled the army pair scan to a 0.4s interval and removed the two per-frame heap allocations. `ArmyManager` now exposes `AllArmies`, a read-only view of the live registered-army list (allocation-free index iteration, always in sync via `RegisterArmy`/`UnregisterArmy`). `ArmyBattleManager.ScanForNewBattles()` iterates that view every `scanIntervalSeconds` instead of copying `GetAllArmies()` every frame, and `UpdateBattles()` reuses a `List<int>` buffer instead of allocating `new List<int>(activeBattles.Keys)` each frame. Battle behavior is unchanged except detection cadence; the spatial grid was intentionally skipped (allowed by the ticket).

## Verification

## Notes / Issues
- **Throttle vs dirty-flag**: chose the interval throttle (the ticket's first option) rather than "skip when cache not dirty" because armies move every frame; a dirty flag only tracked on register/unregister would miss armies that approach each other after being registered, regressing battle detection. Note: `scanIntervalSeconds` is serialized so a scene/prefab holding an existing `ArmyBattleManager` will pick up the default 0.4f; if any scene has a pre-serialized instance, the new field defaults to 0.4f.
- **Alloc-freedom caveats**: `battleIdBuffer.AddRange` may grow the buffer's internal array occasionally (capacity ramp-up), not per-frame garbage. The `$"Need at least 2 armies..."` interpolated log allocates a string but only when diagnostics logging is enabled and throttled.
- **Live-list iteration vs old snapshot**: `GetAllArmies()` previously returned a copy, so an army destroyed mid-scan could not shift indices. Iterating the live list means a mid-scan removal may defer one pair to the next scan — index loops re-read `Count` each iteration, so no out-of-range risk. Acceptable for a strategy game and within the ticket's stated approach.
- **Spatial grid** (Nice to Have) skipped — the ticket allows it; the O(n²) cost is now amortized to 2.5 scans/second.
