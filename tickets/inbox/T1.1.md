# TICKET: T1.1 — Fix Player Raid Loot Penalty

## Context
`RaidManager.GetRaidEffectiveness()` reads `AIManager.Instance.Settings.AIRaidEffectiveness` (0.4) and applies it to **both** player raids (`ExecuteRaid(ProvinceModel, General)`) and AI raids (`ExecuteRaid(ProvinceModel, Army)`). Players currently only get 40% of their calculated loot. This is a bug, not design.

## Must Have
- [ ] Player raids (`ExecuteRaid(ProvinceModel, General)`) use full loot calculation (no AI multiplier)
- [ ] AI raids (`ExecuteRaid(ProvinceModel, Army)`) still use `AIRaidEffectiveness`
- [ ] Add a `PlayerRaidEffectiveness` field (default 1.0) to `AISettings` (or a new `RaidSettings` SO) so player raid tuning is configurable

## Nice to Have
- [ ] Add a debug log showing which multiplier was applied (player vs AI)

## Done When
- [ ] Code review confirms the player raid path no longer calls `GetRaidEffectiveness()`
- [ ] AI raid path still applies `AIRaidEffectiveness`
- [ ] Code compiles cleanly (no syntax errors, all referenced types exist)

## Manual Check
YES — verify in-game that a player raid on a 1000-loot province with 1000 troops yields ~60% loot (not 24%)

## Files Touched
- `Assets/code/RaidSystem/RaidManager.cs`
- `Assets/code/AI/AISettings.cs` (or new `RaidSettings` asset)

## Branch
`feature/t1.1-fix-player-raid-loot`

## Notes for the Agent
- The bug is in `RaidManager.GetRaidEffectiveness()` — it's used by both raid paths. The player path (`ExecuteRaid(ProvinceModel, General)`) should NOT use it.
- `AISettings` is a ScriptableObject. If you add a field there, note that the `.asset` file may need regeneration (see T2.2) — but for this ticket, adding the field with a sensible default is enough.
- Do NOT change the loot calculation formulas themselves — only the multiplier application.
