# TICKET: T1.6 — Quest Tree UI (Scrollable Tree Panel)

## Context
The quest panel is currently a fixed, non-scrollable horizontal row of 5 hardcoded slots in `Assets/Resources/QuestPanelCanvas.prefab` (absolute anchored positions, no layout components, no ScrollRect, no dynamic creation). User wants: a scrollable TREE-style quest screen where quests unlock each other (parent→child relationships visible), and the panel should be more polished.

T1.4 adds ~10 new quests with a tree prerequisite structure, so the panel MUST generate entries dynamically from `QuestManager.allQuests` (the fixed 5-slot prefab cannot work).

## Must Have
- [ ] Rework `QuestPanelController` to dynamically create one `QuestItemUI` entry per quest in `QuestManager.allQuests` (instantiate a quest-item prefab into a content container). Remove the hardcoded `questItems` list pairing.
- [ ] Build the entries in a TREE layout: quests are placed in a tree following `prerequisiteQuestId` relationships (root quests on one row; children below/indented under their parent; arrows/connectors between parent and child). Must handle N levels and branching.
- [ ] Add a `ScrollRect` (with scrollbar or scrollbars) around the tree content so it scrolls vertically and/or horizontally when the tree grows beyond the panel.
- [ ] Beautify: use the MedievalSharp font for titles (via existing `GameFontManager.Apply`), better colors for LOCKED/ACTIVE/COMPLETED/CLAIMABLE/CLAIMED states, show quest title text (currently it shows "QUEST {id}" — change to actual `questTitle`), and show progress "x/y" on active quests.
- [ ] The unlock relationship must be visually clear (child appears locked until parent completes; connector dims/brightens accordingly). Child unlock should refresh live when the parent completes (reuse `OnQuestCompleted`/`OnQuestProgressUpdated`).
- [ ] Keep hover tooltip behavior (QuestTooltip) working for each dynamic entry.

## Nice to Have
- [ ] A close (X) button on the panel.
- [ ] Pan indicator or drag-to-scroll.

## Done When
