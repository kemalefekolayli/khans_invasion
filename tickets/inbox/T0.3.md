# TICKET: T0.3 — GameLog File Sink (headless log output)

## Context
`GameLog` (static logger, `Assets\code\Logging\GameLog.cs`) currently routes only to `UnityEngine.Debug.Log` (Unity console). There is no file sink. For headless agent testing (batchmode runs of the `SimulationController` harness), the console is not inspectable — the test agent needs logs written to disk. This ticket adds a minimal file sink so agent runs produce `Logs\game_log.txt`.

## Must Have
- [ ] A file sink for `GameLog` that appends formatted log lines to a text file (default `Logs\game_log.txt`, path configurable via a `[SerializeField]` on a small MonoBehaviour or a static config).
- [ ] The sink respects the same category/profile filtering as `GameLog` (only enabled categories are written).
- [ ] Writes on a flush-friendly cadence (e.g., flush each line) so a crashed/hung process still leaves readable logs.
- [ ] Disabled automatically when logging is silenced (i.e., `GameLogProfile.Silent` writes nothing to file).
- [ ] `Logs/` is already gitignored — confirm it stays ignored (no repo changes to `Logs/`).

## Nice to Have
- [ ] A timestamp + category prefix per line so the test agent can correlate events (`[AI] [Battle] 2026-08-02 12:00:00 msg`).

## Done When
- [ ] Code compiles cleanly (no syntax errors, all referenced types exist)
- [ ] Calling `GameLog.Log(GameLogCategory.AI, "test")` appends to `Logs\game_log.txt` when file logging is enabled
- [ ] Setting the profile to `Silent` produces no file output
- [ ] No new public API is added that nothing uses (the sink is wired into the existing `GameLog.Log` path)

## Manual Check
YES — open the game, let the AI run a turn, confirm `Logs\game_log.txt` appears with AI logs

## Files Touched

- Possibly one new small file `Assets\code\Logging\GameLogFileSink.cs` (MonoBehaviour or static helper)
- Possibly `Assets\code\Logging\GameLogManager.cs` to wire a serialized path

## Notes for the Agent
- This is deliberately SMALL. Do not add buffering frameworks, rotation, or async complexity. A simple `StreamWriter`/`File.AppendAllText` in the `Log` path is fine.
- Use `Application.persistentDataPath`? NO — use project-relative `Logs\game_log.txt` (already gitignored) so the test agent can find it deterministically.
- Reuse the existing `GameLog.IsEnabled(category)` check; do not duplicate filter logic.
- Anti-slop: no unused members, no new parallel logging system.
